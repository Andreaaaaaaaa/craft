# Review · 质量评审

用于收尾、明确要求的评审及已发现的视觉或行为问题。范围与改动风险相匹配，不把一行间距调整升级为全站审计。

## 证据先于结论

查看真实界面、状态与相关代码。仅有截图时评估可见布局，不能断言键盘、响应式或交互无缺陷。仅有源码时给静态发现，说明运行结果未知。

只要求评审就报告问题，不自动改代码；要求修复或打磨就在授权范围内处理并验证。

## 选择相关检查

| 维度 | 观察什么 | 证据 |
| --- | --- | --- |
| 用户任务 | 能否识别状态与下一步 | 完成关键流程，定位受阻处 |
| 视觉连贯 | 层级、字体、色彩与边界是否支持方向 | 与现有令牌、组件或参考对照 |
| 内容适配 | 长标题、中文、金额、日期、空数据 | 业务中有代表性的真实内容 |
| 响应式 | 裁切、顺序与导航 | 目标窄宽屏，必要时加中间尺寸 |
| 可访问性 | 语义、焦点、对比、键盘和减少动态效果 | 实际操作与工具检查，自动扫描不等于完整认证 |
| 状态恢复 | 加载、失败、空态、重复操作后能否继续 | 模拟与改动相关的状态 |
| 性能 | 响应、滚动、布局跳动、素材与动画成本 | 可复现表现，有需要再测量 |

复用现有测试与检查。逻辑、状态机或回归风险改变时补有价值的测试；视觉微调优先渲染和操作，不编写只检查 CSS 字面值的测试。

## 按场景验证行为

从下表选择与实际改动有关的条目，不给页面补齐不存在的功能，也不要求每次执行整表。先说明用户动作和预期结果，再选择手动操作、现有测试或诊断工具来验证。

| 场景 | 关键检查 |
| --- | --- |
| 表单 | 校验信息与字段关联；提交防重；失败保留输入且能重试；受控值与初始值不冲突 |
| 数据表格 | 行标识稳定；排序、筛选与分页使用同一数据规则；筛选后页码有效；刷新和翻页后的选择状态符合产品约定 |
| 搜索与远程选择 | 区分本地与服务端过滤；旧请求不会覆盖新查询结果；清空、无结果与加载状态明确 |
| 上传 | 进度与实际结果一致；失败可重试或移除；文件列表由谁管理清楚；取消后不误报成功 |
| 对话框与菜单 | 打开与关闭后的焦点位置合理；键盘能完成操作；Escape、外部点击与未保存内容按产品约定处理 |
| 路由与权限 | 入口可见性、页面访问与服务端授权一致；隐藏按钮不被当作权限控制 |
| 流式内容与工具调用 | 处理中、结束、失败和取消可区分；重试不重复执行有副作用的动作；消息和工具结果关联稳定 |
| 服务端渲染 | 首屏与客户端接管一致；样式加载顺序稳定；浏览器专有 API 不在服务端执行 |

组件相关改动同时检查 API 是否适用于项目版本。使用项目已有的类型检查、lint 或组件诊断工具验证变更路径；这些检查不能替代实际行为验证。遇到工具异常时记录证据并选择合适的替代检查，不自动升级依赖或向外部提交报告。

## 给出可执行反馈

先报告阻止任务、误导操作、隐藏内容或不可访问的问题，再报告层级与一致性，最后是偏好。每个发现包含位置或触发条件、可见问题、用户影响和修复方向，标明未确认推断。

建议应保留确定的方向。用户要求柔和渐变时，不能仅凭常见就要求黑白；需要可读性等具体证据。

## 收尾门槛

确认请求已实现、关键流程可用、相关尺寸未破坏、无未说明的占位与假功能。修正后复验受影响部分，无新证据时不为主观评分不断改版。

交付区分已完成、实际验证、尚未验证。不能运行时说明原因与剩余验证步骤，不说全部通过。
